# POC 1 — ADAS Data & Human-in-the-Loop Workflow

> Synthetic data and simulated perception. This is not a production autonomous-driving model, and no real camera or LiDAR data is used.

## The problem

ADAS and autonomous-driving systems need enormous amounts of accurately labeled data.

- **Manual labeling alone** is slow, expensive and difficult to scale.
- **AI-only labeling** is fast, but incorrect labels silently enter the training dataset — and the model then learns its own mistakes.

The solution is to use both, and let confidence decide who does what:

**AI auto-label + confidence scoring + human review + feedback loop**

## The workflow

```
Camera / LiDAR
      ↓
Data Ingestion
      ↓
Validation
      ↓
Auto Labeling
      ↓
Confidence Score
      ├── HIGH   (≥ 0.90)       → Accept
      ├── MEDIUM (0.70 – 0.89)  → Sample Review
      └── LOW    (< 0.70)       → Human Review
                                      ↓
                                  Correction
                                      ↓
Dataset Version
      ↓
Model Training → Evaluation → Deployment
      ↓
Production Monitoring
      ↓
Edge Case Mining
      ↓
Next Training Dataset   (and around again)
```

## How each stage is implemented

### 1. Mock sensor data — `backend/app/data/generator.py`

5,000 driving frames. Each has `frame_id`, `vehicle_id`, `timestamp`, GPS position, `speed_kmh`, `weather` (clear, rain, heavy_rain, fog), `lighting` (day, night, dawn, dusk), `road_type` (urban, highway, residential, intersection, tunnel), `camera_front_path`, `lidar_available`, the detected objects, `model_confidence`, `label_status`, `review_required`, `dataset_version` and `scenario_category`.

Frames are generated by scenario so that difficult situations are present in known quantities — for example 342 "motorcycles in heavy rain" and 198 "night pedestrian crossing" frames.

### 2. Auto-label engine — `backend/app/services/adas_label_engine.py`

Each simulated detection starts from a per-class base confidence and loses confidence for each difficulty factor:

| Factor | Penalty |
|---|---|
| Tunnel lighting transition | −0.29 |
| Occlusion | −0.21 |
| Heavy rain | −0.14 |
| Fog | −0.11 |
| Night | −0.10 |
| Pedestrian near road | −0.10 |
| Motorcycle between cars | −0.10 |
| Rain | −0.05 |
| Small object | −0.05 |

Environmental penalties weigh more heavily on vulnerable road users (motorcycles, bicycles, pedestrians) than on large vehicles. A little random noise is added.

**Frame confidence is the minimum over its labels** — a frame is only as trustworthy as its weakest label.

### 3. Routing

| Confidence | Route | What happens |
|---|---|---|
| ≥ 0.90 | **Auto accept** | Labels go straight to the dataset |
| 0.70 – 0.89 | **Sample review** | Accepted, but a quality-control sample is sent to humans, weakest first |
| < 0.70 | **Mandatory human review** | Held out of training until a person decides |

### 4. Human review — `review_service.py`, *Human Review* page

The reviewer sees the frame, the AI detections with confidences and the reasons confidence is low. Four actions:

- **Accept** — all labels confirmed
- **Correct** — change the class, set the corrected confidence, adjust the bounding box
- **Reject** — exclude the frame from training
- **Add object** — label something the model missed

On a correction the console shows **"HUMAN FEEDBACK CAPTURED — Correction will be added to Dataset v24."** The frame is written back with `source: human` on the corrected label, its original AI class and confidence kept for audit.

### 5. Dataset versioning — *Training Datasets* page

| Version | Frames | Status |
|---|---|---|
| ADAS-v21 | 1.7M | Production |
| ADAS-v22 | 1.9M | Archived |
| ADAS-v23 | 2.1M | Current |
| ADAS-v24 | 143K new | Building |

Every review increments ADAS-v24's frame, human-correction and edge-case counters live. Each version records its class, weather and city distribution so the shift toward hard scenarios is visible.

### 6. Edge case mining — `edge_case_engine.py`

Frames are grouped by scenario. For each: number of events, average confidence, an estimated error rate, a priority, and how many extra frames to request.

| Scenario | Events | Avg confidence | Error rate | Priority |
|---|---|---|---|---|
| Motorcycles in heavy rain | ~342 | ~61% | ~22% | CRITICAL |
| Night pedestrian crossing | 198 | ~70% | ~15% | HIGH |
| Tunnel entry | 86 | ~69% | ~16% | HIGH |
| Truck occlusion | ~157 | ~73% | ~13% | MEDIUM |

The top scenario produces the recommendation: *"Add 2,500 additional night/rain motorcycle frames to next training cycle."*

### 7. Model dashboard — `model_metrics.py`

Precision, recall, mAP, false-positive and false-negative rate for **ADAS Vision v5 vs v6**, broken down by object class, weather, day/night, city and vehicle type.

Why human feedback matters (mock demo data):

| Metric | Before feedback | After feedback |
|---|---|---|
| Pedestrian recall | 81.4% | 89.7% |
| Motorcycle recall | 76.2% | 87.1% |

## The killer demo

1. The model detects a motorcycle between two cars, in heavy rain at dusk, at **58%** confidence.
2. 58% is below 0.70, so the frame is routed to mandatory human review.
3. A reviewer confirms the class and tightens the box.
4. The corrected frame is versioned into **Dataset v24**.
5. The simulated next model candidate improves on exactly that scenario.

This runs as steps 8–11 of **RUN AI DEMO**, and can be done by hand on frame `FRM-004242`.

## What is simulated, precisely

| Element | Reality in this demo |
|---|---|
| Camera frames | SVG road scenes drawn from frame metadata |
| Detections and boxes | Generated geometrically; no model inference |
| Confidence | Rule-based, as described above |
| Error rate | `0.75 × (0.90 − average confidence)` — a stand-in calibration curve, not audited ground truth |
| Model metrics | Authored numbers |
| Candidate uplift | A fixed mock increment per human correction, capped |

In production the confidence would come from a calibrated perception model, the error rate from audited samples, and the uplift from an actual retraining run evaluated on a held-out edge-case set.
